Money and rounding

Amounts are exact fractions. Rounding is a decision, so it has a name and happens where you put it.

amount("$1,234.56");                    // 30864/25
amount("4.5%");                         // 9/200
round("2.345");                         // 117/50 = 2.34
round("2.345", { mode: "half-up" });    // 47/20 = 2.35
format("1234567.891");                  // "1,234,567.89"
allocate(100, [1, 1, 1]);               // 33.34, 33.33, 33.33

Why not floating point

One tenth has no finite binary expansion, so 0.1 in a double is 0.1000000000000000055…; ten of them do not make 1, and a column of such numbers need not add to its total. The error is tiny each time but it is not zero, and rounding to the cent at the end can then go the wrong way. With rationals \(1/10 + 2/10 = 3/10\) and nothing else is possible.

Rounding rules

When an exact amount such as 1498.876313… must become a payable one, a rule is needed for the half-way cases and for the direction:

places may be negative: round(1250, { places: -2 }) is 1200 under half-even. Functions that produce schedules take a rounding option: { places, mode }, a number of places, or false for none.

Splitting without losing a cent

A third of 100.00 is 33.33⅓. Rounding each share gives 99.99 or 100.01. allocate rounds every share down and hands out the cents left over to the shares that lost most (the largest-remainder method), so the parts always add to the total.

Showing numbers

format(x, { places, mode, currency, separator, percent }) writes an amount for people. show(x, places) is the plain version used throughout these pages, and it also accepts an interval: if both ends round to the same decimal, that decimal is the correctly rounded answer and is printed; if a rounding boundary lies inside the interval, both ends are printed, and asking for more digits from the function that made it will settle the matter.
